# 需求适配与追问升级

目标是让同一个聊天入口按用户明确需求做事，同时完善混合记账、连续补充、纠错和资料导出。沿用现有布局和视觉体系；“记住的事”增加可读的需求偏好，投资面板复用现有导出入口样式。

| 可以这样说 | 当前行为 |
| --- | --- |
| 我只想记账，不要分析 | 保存明确记录，追问记账必需信息；不主动追加预算追问或模型分析。已知预算缺口仍可提示 |
| 我想控制开支 | 关注生活余量，逐项补齐月初现金、必要开支、应急预留 |
| 我想长期稳健投资 | 保存投资关注点与明确表达的风险偏好；缺少期限时询问；模型请求带上这些资料 |
| 回答简短一点 / 详细一点 | 采用简短归档反馈，或补充每笔明细；模型分析提示使用对应表达方式 |
| 这次不要记住 | 本段新增记录不进入重点记忆；账本与原始聊天保留 |
| 以后不要记住 | 停止展示和引用逐条重点摘要；必要收支汇总仍用于预算；可忘记偏好重新选择 |
| 工资到账了，午饭实付了，订阅了 GPT Pro，计划买基金 | 一次保存四项待补充事项，逐条问金额；只在事实状态明确时计入统计 |
| 跳过 / 继续核对 | 暂缓当前事项，之后可继续；新事项缺信息仍会询问 |
| 昨天午饭改成二十八 | 根据日期、类别和餐次定位；多条候选先选择，不批量覆盖 |
| 订阅花了多少 / 昨天收支 | 按指定类别或时间汇总，币种分开，计划与待核对不计入已发生收支 |
| 打开投资计划 / 导出投资计划 | 展开结果或提供 CSV 下载，不将命令写成一笔投资 |

金额提取、分类和工作流选择仍采用确定性规则；外部模型只在用户提出分析时调用。本次没有训练模型、增加资金执行能力、接入新的行情或优惠供应商，也没有公网部署。

追问状态仅归属于当前会话，偏好与账本按访问者会话隔离并在本机保存。更正工资会联动相关比例计划，计划未执行。偏好仅接受明确表达，否定和转述不会直接当成用户选择，不生成职业或财富等级画像。

## 验证

- 59 项 Python 检查通过：原有记账/接口/模型契约检查，加上需求适配、多条追问、中文金额、跳过、偏好隔离、摘要控制、无标点分句、定向纠错、分类查询、单独导出和命令不入账。
- 原有浏览器路径在 1440 / 390 / 320 宽度通过，覆盖输入、保存、修改、删除、导出、刷新、网络失败草稿和访问者隔离。
- 新增浏览器路径在 1440 / 390 宽度通过，覆盖逐项补充、只记账、偏好面板、投资 CSV 实际下载、相似记录选择、预算模式切换、本次不记住、刷新恢复和忘记偏好。
- 新的模型提示词通过注入测试替身检查，确认明确偏好进入请求；本次未重新进行外部模型可用性验收。此前观察到的间歇不可用边界仍适用。

执行 `python -m unittest discover -s tests -q`；本机测试服务启动后运行 `node tests/browser_conversation.cjs` 和 `node tests/browser_needs.cjs`。测试使用独立 Cookie 与 `artifacts/` 下的测试数据库，不修改用户的试用数据。
